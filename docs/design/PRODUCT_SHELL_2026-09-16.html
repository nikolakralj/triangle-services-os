Triangle Operating Shell

Where the product is going: one inbox where you make the decisions only a person can make, three employees who do the work on their own bots, and one record underneath that both sides trust.

The pictureFour layers, and what moves between them

Everything in Triangle is one of these layers. You never work in the employees' layer, and they never make your decisions. Triangle in the middle is the only place work lives: a Grok chat, a mailbox or a webhook are ways in and out, not places to keep anything.

What changesFive decisions in this proposal

The menu becomes Today · Missions · Talent

Workforce leaves the menu. The employees move to Settings → Team. Signal Inbox, Cert Alerts, Compliance, Setup Readiness and Data Imports go into Talent or Settings.

Today is one inbox

Needs you, a quiet In progress line and Done since you looked. No system errors, no mission grid, no second Ask box, no history backlog.

All delegated work is a task on a case

Each task has a case, an owner (you), an employee, a state and a thread. The same six states appear everywhere, modelled on the open A2A standard.

Employees talk inside the case

When Hanna asks Scout for buyers, it shows in that case's thread. It reaches you only if someone needs a human answer.

Engineering stays out of the company

The programming bot gets its own account, test data never goes into the live company, and only merged code is published.

The unit of workA task on a case

This is the idea everything else follows. It is already how DEV-015 works ("handoff changes the owner, not where the work lives"); this makes it the rule for every screen. Linear and GitHub work the same way: you delegate the work item to an agent, you stay the accountable owner, and the agent's activity lives inside that item, not on an agent page.

CommunicationFour paths, one record

What passes between people, employees and the world. Each path writes to the same task and thread, so there is nothing to copy between screens. Most of this is built; the labels say what is not.

You → an employeebuilt; page context is DEV-010

Ask on the page you are on→task on that case→bot woken→activity in the thread→result on the case, or Needs you

Employee → employeebuilt 14 September

Hanna asks Scout for buyers→child task on the same case→Scout answers→Hanna is woken

You see it in the thread. It reaches you only as Needs you.

The world → an employeeoutbox built 16 September; mailbox observation next

reply arrives · follow-up due · availability stale→task for the owner→employee handles it→Needs you only for a judgment

Machines observe, humans judge: no buttons for things the mailbox can see. Needs the mailbox you reply from connected (question 1).

Triangle → the worldSend is DEV-013

employee drafts→you edit and press Send→ledger keeps draft, final text, time, follow-up

Employees send nothing on their own unless a message kind is set to automatic. Prices, rates, dates, headcount and contracts are never an employee's to commit.

Scout's real result was 12 EU HVAC buyers. The likely cause is that the programming bot and Scout share one Grok account, and bots in one account share a computer and its context.
