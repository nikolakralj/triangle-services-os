Triangle Workforce Architecture

Can Scout, Hanna and Bob become managers who delegate to other Bots, with Triangle holding every fact and decision? What Grok Bot actually supports today, what it doesn't, and the architecture that follows.

Document
TSOS-ARCH-001
Revision
A · 13 Sep 2026
Status
Research only — no code
Platform
Grok Bot (beta since 11 Aug 2026)
Verdict

Grok does the labour. Triangle must own the orchestration.

  1. Triangle can wake a Bot but cannot command one. A webhook routine starts a run; there is no documented API to message a Bot, assign it work, or wait for a structured result. Everything of record has to flow back through Triangle's own API.
  2. A Marketplace Bot is a template, not a contractor. Installing one creates a copy in your account, on your computer, with your logins. "Hiring a specialist for one task" is not a platform concept.
  3. Bots under one user are one security principal. They share the computer, browser sessions, files and connectors. Separate mailboxes per Bot isolate nothing; separate Cursor users do.
  4. Choose architecture B — but the front door is Triangle's software (missions, assignments, approvals), not a fourth chat Bot. Three persistent managers; delegation between them goes through Triangle as assignments.
  5. Prove one chain before building any registry: Nikola → Scout → Hanna → Bob → Nikola approves, with every hop an assignment Triangle can see, retry and audit.
A · What is technically possible today

Confirmed platform capabilities

Only official xAI and Cursor documentation counts as confirmed; Observed means we saw it in Triangle's own production on 12 September.

What Triangle can start programmatically

  • Wake one specific Bot through its webhook routine (POST + key) Observed
  • Serve state and accept results through its own API or an MCP connector the Bot calls
  • Rely on scheduled routines as a backup clock
  • Launch Cursor Cloud Agents with up to 20 subagents via API — separate from Grok Bots

What it cannot

  • Send a message to a Bot or into a group chat
  • Assign a task and await a structured result
  • Create a Bot, add a Bot to a group, or spawn parallel Bots
  • Invoke a Marketplace Bot without installing it as a full-access Bot

Triangle database — the only truth

Why not a "Triangle AI" Bot on Grok as the front door? It would be a fourth Bot on the same computer, with the same logins, keeping a second copy of the state in its conversation — and Triangle could not drive it anyway, because there is no API to message it. Ctrl+K in Triangle already is the single interface; what's missing is routing an outcome across managers, which is software.

H · Orchestration model

If it isn't an assignment in Triangle, it didn't happen

  1. An outcome becomes a mission with a finish line counted from records. EXISTS
  2. Triangle routes it to one owner and wakes that Bot. EXISTS for Scout
  3. The owner delegates across domains by creating a child assignment through Triangle's API — objective, output contract, budget, deadline. Triangle wakes the assignee. A Grok chat handoff alone is never the record. TO BUILD
  4. The assignee works with its own tools and files results with sources against the contract. EXISTS for targets
  5. Gates before anything counts: cheap rules first (channel on the cited page, duplicates, required fields); a second-model verifier only for failures and for facts that trigger contact or a commitment. TO BUILD
  6. Completion only through Triangle; the parent recounts its progress from records. EXISTS
  7. Stalls are re-woken on a timer; after a set number of attempts, a person is asked. PARTLY
  8. Budgets per mission and per assignment; over budget means stop and ask. TO BUILD
  9. Every external action is a draft awaiting approval in Triangle, with the approver recorded. PARTLY

I · Security and credential model

Five identities that must not be conflated

IdentityWhat it isSecurity boundary?
Bot personaName, role, memory, skills — Scout, Hanna, BobNo
Compute principalThe Cursor user: its computer, browser sessions, files, connectorsYes — the only one on Grok
Service accountA SaaS login a principal uses: jobs@, sales@, an Apollo seatYes, inside that system
Human accountNikola's Gmail, WhatsApp, LinkedIn — personal identity and legal accountabilityMust stay off Bot computers
Triangle identityagent_instance plus badge scopesAttribution only on a shared computer — any Bot there can read a token kept in a file

scout@, hanna@, bob@ — does it work?

As service accounts, yes, and it's good hygiene: each costs a seat in Google Workspace, Apollo or whatever system issues it. But on one Cursor user all three logins are available to all three Bots, so separate mailboxes don't separate the Bots. Separate by risk, not by persona:

  • Research principal: Scout. Reads untrusted web pages all day, so it holds a Triangle badge and nothing personal or send-capable.
  • Communications principal: Bob, and Hanna's candidate drafting. Holds the business mailboxes and calendar; browses little; strictest approval rules.
  • Nothing personal on either. Your WhatsApp, Gmail and LinkedIn stay on devices you operate.

Each extra principal is another Cursor seat and another computer to sign in and maintain — so two principals, not three.

Bob answering your WhatsApp — stop the automatic replies

  • It's L4 on your identity with no approval. Your own rules put contacting anyone outside Triangle with a person.
  • Anyone who messages you can now address a Bot that holds your account — including instructions hidden inside a message. The platform itself says such controls reduce, not eliminate, that risk.
  • On a shared computer, every Bot of that user can use the session — including Scout, which reads arbitrary web pages. Whether Bob runs on the same Cursor user, or as a desktop agent on a Windows PC, is worth confirming.
  • WhatsApp's guidelines forbid auto-messaging, auto-dialing, or automation to harm WhatsApp or our users, with suspension as the remedy — a real risk to the number your clients and candidates know.
  • Client and candidate messages would be processed on US-hosted computers.

Instead: let Bob draft replies for you to send, or move business chat to the WhatsApp Business Platform with a business number.

J · MVP

One delegation chain, with Triangle holding all state

Your chain, with the one change from section D — the buyer stays with Scout, and Hanna contributes the crew — built on the Austria mission that already has 8 verified doors:

Nikola · one instruction→ Triangle mission→ Scout · requirement + verified door→ Hanna · crew from confirmed people→ Bob · first-contact draft→ Nikola approves and sends→ Bob · follow-up date

Passes when

  • One instruction from Nikola, nothing more
  • Every hop is a Triangle assignment with its parent
  • Every door passes the source check
  • The crew uses only people confirmed in 14 days
  • Zero messages sent by a Bot
  • Time and cost per hop are recorded

Build only this

  • Child assignments created with a badge
  • Wake-ups and the bot switch for Hanna and Bob
  • The source check at filing
  • Bob's draft with approve-and-send by a person
  • The chain shown on the mission page

Not now: registry, scores, Marketplace hiring, event bus, a Triangle chat Bot.

L · Push back

Where the plan overreaches

  1. A "Triangle AI" Bot duplicates the front door. It would be a fourth Bot and a second source of state, and Triangle couldn't drive it. The app is the interface.
  2. Marketplace Bots aren't hireable specialists. Installing one gives a stranger's instructions your logins. Use them as skill sources after reading them.
  3. Architecture C and an AI labour market need volume you don't have. Scores from tens of jobs a week are noise.
  4. The buying committee isn't Hanna's. Buyer contacts and candidates have different legal purposes; keep them apart.
  5. Separate mailboxes don't separate Bots. Only separate Cursor users do.
  6. Grok chats aren't a record. No structured results, 20 run records per routine, text-only group handoffs.
  7. Parallel swarms are discouraged by the platform itself — too many parallel handoffs duplicate work.
  8. Which model is smartest doesn't change the architecture. Keep the brain swappable, as you decided on 11 September.
  9. Orchestration isn't the Phase 0 bottleneck. Human-sent messages, buyer conversations and a delivered placement are. Build the chain that ends in a send.
  10. The platform is in beta, with open bug reports on webhooks and custom connectors. Keep every hop durable on Triangle's side.
